# Автоматические проверки

## Запуск

Из корня репозитория:

```powershell
.\mvnw.cmd verify
```

В Linux/WSL: `sh ./mvnw verify`. Только тесты — цель `test`, сборка с удалением
старых артефактов — `clean verify`. Нужны JDK 21, Bash и Python 3.10+.
API-ключ и настоящая модель не требуются.

На Windows тесты ищут Git Bash в `C:\Program Files\Git\bin\bash.exe`, Python —
в `C:\msys64\ucrt64\bin\python.exe`; иначе используются `bash` и `python3` из PATH.
Пути можно передать явно:

```powershell
.\mvnw.cmd verify '-Dtest.bash=C:\path\bash.exe' '-Dtest.python=C:\path\python.exe'
```

Эти свойства задают окружение тестов. Приложение получает пути через `--bash`
и `--python`. Отчёты JUnit находятся в `target/surefire-reports`.

## Организация

Тесты находятся в `src/test/java/dev/codingagent` и повторяют пакеты основного кода.
`support/ProjectFixture` создаёт отдельный проект и SQLite-базу для каждого теста;
`support` также содержит подготовленные ответы модели и общие заготовки.
HTTP-тесты используют локальный сервер. Интеграционные тесты исполняют настоящий
Bash и Python во временных каталогах.

Контрольный проект копируется из `workspace`: тесты проверяют исправление
`order.py`, реальный запуск `unittest` через Bash и неизменность `test_order.py`.
JSON-сценарии в `examples` используются также в примерах CLI из README.
CLI-тесты исправления и diff явно задают исходную ошибку во временном проекте,
чтобы результат не зависел от предыдущего ручного запуска в `workspace`.

## Покрытые сценарии

Пути классов ниже указаны относительно `src/test/java/dev/codingagent`.

| Область | Проверки | Классы тестов |
|---|---|---|
| Цикл агента | Несколько вызовов в ответе, ошибки инструментов, обратная связь при повторной одинаковой ошибке, сохранённые вызовы до нового запроса модели, завершение по фактической проверке Bash | `agent/AgentTest` |
| Инструменты | JSON Schema, неизвестное имя, неверные и лишние аргументы, границы workspace, настоящие операции с файлами | `tools/ToolRegistryTest` |
| Bash | Рабочий каталог, кавычки, UTF-8, stdout/stderr, код завершения, таймаут, остановка процесса и обрезка вывода | `tools/bash/BashToolTest` |
| API | История и схемы в запросе, JSON Schema без инструментов при формировании плана, сохранение полного сообщения assistant и исключение reasoning из отправляемой копии, диагностика пустого ответа с finish_reason, авторизация и HTTP-ошибки | `model/ChatCompletionsClientTest`, `model/ModelConfigTest` |
| Сценарный клиент | При исчерпании ответов показывается последняя ошибка инструмента; исправленная предыдущая ошибка не выводится как причина | `model/ScriptedModelClientTest` |
| JSON | Сохранение полных объектов, защитные копии, строковый content в API, сравнение чисел и ключей, отказ от дублированных ключей | `model/JsonPayloadTest`, `json/JsonTest` |
| Запуск и SQLite | Полная история после открытия другой базой, переходы статусов, отдельные пути, атомарный update и откат при SQL-ошибке, отказ от старого и неполного формата | `run/RunServiceTest`, `storage/StateStoreTest` |
| Повтор вызова | Тот же ID не повторяет действие; изменённое определение даёт ошибку; новый ответ assistant получает соответствующий role=tool | `tools/execution/ToolCallServiceTest`, `agent/AgentTest` |
| Восстановление | Сбой после действия до сохранения, различие ожидающих и неопределённых вызовов, retry/skip/fail, новая попытка, запрет повтора записи и Bash, атомарность решения | `run/recovery/RecoveryTest` |
| Plan Mode | Чтение до утверждения, запрет записи и любого Bash, проверка структуры, approve/reject, набор инструментов текущего шага, продолжение формирования плана после ошибки API без повторного чтения | `plan/PlanModeTest`, `plan/WorkPlanTest` |
| CLI | Команды plan/approve/reject/resume/show/tasks с общей базой, чеклист, продолжение после локального лимита и исправление проекта с Bash по умолчанию | `cli/CliWorkflowTest` |
| Бюджеты | Исчерпание каждого лимита, отказ всей пачки, общий расход фаз и resume, списание до запроса, конкурирующие допуски и ошибки сохранения | `budget/BudgetTest` |
| Размер вывода | Полный JSON в UTF-8, экранирование и Unicode, передача остатка инструменту, truncated, расход резерва после сбоя и при повторе | `budget/OutputBudgetTest` |
| Задачи | Минимум три задачи с зависимостями, проверка графа, назначение task_id, сохранение статусов и подтверждений, отсутствие повтора завершённых задач | `task/TaskGraphTest`, `task/TaskRuntimeTest` |
| Подтверждения | Ошибка, обрезка, другой путь или задача не завершают работу; старый Bash из кеша не подтверждает изменения; завершение и подтверждения атомарны | `task/TaskEvidenceTest`, `agent/AgentTest` |
| Журнал | Скрытые и бинарные файлы, каталоги, точные байты и хеши, изменения через Bash с ошибкой, внешние создание/изменение/удаление до STARTED | `journal/JournalTest` |
| Неопределённые изменения | Просмотр diff, include/exclude, устаревший observation, конфликт на ранее принадлежащем запуску пути и атомарность решения | `journal/JournalRecoveryTest` |
| Откат | Diff, исходные байты после перезапуска, конфликт до записи любого файла, сохранение посторонних путей, замены типов, продолжение после сбоя и повтор завершённого отката | `journal/rollback/RollbackTest` |

Тесты с SQL-триггером воспроизводят ошибку сохранения, чтобы проверить атомарность
связанных данных. `ExecutionHook` воспроизводит разрыв между действием в файловой
системе и записью результата. Для ручного повторения используется
`--crash-after-call`, описанный в [README.md](../README.md).

Детерминированные сценарии проверяют runtime с известными ответами модели.
Они не оценивают качество решения выбранной внешней моделью.
